## Language and types

| Status | Feature | Notes |
| --- | --- | --- |
| <Icon icon="flask" iconType="solid" size={16} color="#7C3AED" /> | [Describe a shape](/language/shapes-and-constraints) | Structural types and built-in constraints; compile-time checks where values are static, runtime validation via `ensure` in the body. Parameter prologue emission is future work. |
| <Icon icon="circle-check" iconType="solid" size={16} color="#16A34A" /> | [`ensure`, `is`, and shape guards](/language/check-a-value) | Runtime checks tied to types; static refinements persist until dependency write; typed failure via `else`, assertion `or`, and bare name type targets. |
| <Icon icon="circle-check" iconType="solid" size={16} color="#16A34A" /> | [Refinement stability under mutation](/language/check-a-value#when-a-later-write-drops-the-fact) | Analyzable refinements reuse facts across statements; writes to dependency fields or pointer slots invalidate facts; unrelated writes keep facts. |
| <Icon icon="circle-check" iconType="solid" size={16} color="#16A34A" /> | [Nil and presence checks](/language/check-a-value) | `ensure x is Nil()`, `ensure !x`, and `*T` `.Present()` / `.Nil()` on pointers. Not full optional value types yet. |
| <Icon icon="circle-check" iconType="solid" size={16} color="#16A34A" /> | [Type guards](/language/name-a-rule) | Domain predicates attached to declared domain types (`is (password Password) Strong { … }`); fail-closed logic and assertion `or` support. |
| <Icon icon="flask" iconType="solid" size={16} color="#7C3AED" /> | [Result and named errors](/language/named-errors) | `Result(S, F)`, `error X { … }`, and `ensure` / `if x is Ok()` narrowing. Closed named error unions (`ParseFailed \| IoFailed`) emit sealed Go interfaces. Failure keyword is `else`. See also [Functions that can fail](/language/result). |
| <Icon icon="circle-check" iconType="solid" size={16} color="#16A34A" /> | Control-flow narrowing | Sequential narrowing, if-else branch merging, and field path tracking work end-to-end. |
| <Icon icon="circle-check" iconType="solid" size={16} color="#16A34A" /> | Type aliases | Nominal type declarations (`type Password = String`) own guards and type targets. |
| <Icon icon="flask" iconType="solid" size={16} color="#7C3AED" /> | Binary types (`A \| B`, `A & B`) | Named homogeneous literal unions (`"todo" \| "done"`, `1 \| 2`) and error unions done with exhaustive switch checks; general unions and intersections remain experimental. |
| <Icon icon="calendar" iconType="solid" size={16} color="#64748B" /> | Optional types (`T \| Nil`) | Planned: Crystal-style `T \| Nil` / `T?` unions, narrowing, and Go lowering. See [optionals RFC](https://github.com/forst-lang/forst/tree/main/examples/in/rfc/optionals). |
| <Icon icon="calendar" iconType="solid" size={16} color="#64748B" /> | User-defined generics | Type parameters on types and functions. |
| <Icon icon="circle-check" iconType="solid" size={16} color="#16A34A" /> | Postfix `++` / `--` and compound assignment | `+=`, `-=`, `*=`, `/=`, `%=`, `&=`, `\|=` as standalone statements and in `for` post clauses (`lang_probe/59_inc_compound`). |
| <Icon icon="circle-check" iconType="solid" size={16} color="#16A34A" /> | Shift / xor compound assignment | `^=`, `<<=`, `>>=`, `&^=` and bitwise operators (`^`, `<<`, `>>`, `&`, `\|`, `&^`), including `byte` with `Int`. Hex / octal / binary integer literals keep their spelling under `forst fmt`. |
| <Icon icon="circle-check" iconType="solid" size={16} color="#16A34A" /> | `switch` / `case` / `default` / `fallthrough` | Go-faithful tag and boolean `switch`, including `fallthrough`. Type switches (`switch v := x.(type)`) are omitted; use `is` narrowing instead. |
| <Icon icon="circle-check" iconType="solid" size={16} color="#16A34A" /> | Labeled `break` / `continue` and `goto` | Labeled loop control and `goto label` with Go spec jump rules. |
| <Icon icon="circle-check" iconType="solid" size={16} color="#16A34A" /> | `const` / `iota` | Top-level `const` (single and grouped) with Go `iota` semantics. |
| <Icon icon="calendar" iconType="solid" size={16} color="#64748B" /> | `select` | Not a Forst keyword yet; blocked on channel support. |
| <Icon icon="flask" iconType="solid" size={16} color="#7C3AED" /> | Slice subslice expressions | `xs[low:high]`, `xs[low:]`, `xs[:high]` on Forst `[]T` values. |

## Go interoperability

| Status | Feature | Notes |
| --- | --- | --- |
| <Icon icon="circle-check" iconType="solid" size={16} color="#16A34A" /> | Transpile to Go | Packages, types, and functions emit as readable Go for `go build`. |
| <Icon icon="circle-check" iconType="solid" size={16} color="#16A34A" /> | Validation from constraints | Compiler emits runtime checks from type constraints. |
| <Icon icon="flask" iconType="solid" size={16} color="#7C3AED" /> | Providers (`use` / `with`) | Transitive obligation chains, Go lowering, and cross-package fixed-point (emit-time shims, no committed Go stubs). RFC GA gaps (LSP polish, discovery JSON, sidecar host patterns) remain. |
| <Icon icon="flask" iconType="solid" size={16} color="#7C3AED" /> | Import and type-check Go packages | `go/packages` loading and Forst↔Go call checking; common stdlib paths work. Forst `func` literals assign to concrete Go `func` parameters. Interface fields accept concrete handlers (e.g. `ServeMux` into `http.Server.Handler`). Crypto hash / HMAC constructors type-check as function values. Forst sibling imports resolve from `.ft` in the same module and from `go.mod` dependencies via import-graph discovery + `.forst/overlay/` emit. Failed loads surface as `go-import` diagnostics. |
| <Icon icon="flask" iconType="solid" size={16} color="#7C3AED" /> | Named Go types in Forst signatures | Imported Go named types (e.g. `os.File`, `exec.Cmd`) map to qualified Forst type names and emit as Go selectors. `new(imported.T)`, `&imported.T{…}`, and methods after construction work. |
| <Icon icon="flask" iconType="solid" size={16} color="#7C3AED" /> | Go composite types (maps, channels, arrays, funcs) | `map[K]V`, `[N]T`, `chan T`, and `func` types map at the boundary. Exported-field anonymous structs map to Forst shapes. Some Go type-alias identity gaps remain. |
| <Icon icon="flask" iconType="solid" size={16} color="#7C3AED" /> | Variadic spread into Go calls | `argv[1:]...` at Go call sites. |
| <Icon icon="flask" iconType="solid" size={16} color="#7C3AED" /> | Fields and methods on Go values | Dotted chains on Go-typed bindings (e.g. `cmd.ProcessState.ExitCode()`). |
| <Icon icon="flask" iconType="solid" size={16} color="#7C3AED" /> | Mixed `.ft` and `.go` modules | Adopt beside hand-written Go in one module tree. Same-package unexported symbols resolve when `.go` is co-located. `forst test` includes sibling Go; `forst run`/`watch` can emit beside the package when `generate.go` is set. |
| <Icon icon="flask" iconType="solid" size={16} color="#7C3AED" /> | Generic Go API consumption | `slices.Contains`, `maps.Clone`, and similar APIs instantiate at call sites via type inference. |
| <Icon icon="calendar" iconType="solid" size={16} color="#64748B" /> | Selectable Go emit target version | Emit for `go` toolchains older than the compiler's own version. |

## What Forst omits

These are deliberate **anti-features**—not backlog gaps. Forst excludes them when they would hide control flow, surprise with errors, or break compile-time reasoning.

| Status | Topic | Notes |
| --- | --- | --- |
| <Icon icon="ban" iconType="solid" size={16} color="#DC2626" /> | `panic` / `recover` as language constructs | Non-local, implicit control flow. Forst steers toward explicit `Result` and Go `error` returns. Generated Go or third-party code may still panic. |
| <Icon icon="ban" iconType="solid" size={16} color="#DC2626" /> | Exceptions (`try` / `catch` / `throw`) | Stack-unwinding surprises. Aligns with Go `(T, error)` and `Result(S, F)` instead of TS/Java-style exceptions. |
| <Icon icon="ban" iconType="solid" size={16} color="#DC2626" /> | Class hierarchies and deep inheritance | Inheritance obscures which fields an API has. Forst favors structural shapes and function-centric APIs. |
| <Icon icon="ban" iconType="solid" size={16} color="#DC2626" /> | Macros and preprocessors | Control-flow changes must use ordinary keywords, not compile-time rewrites that hide behavior. |
| <Icon icon="ban" iconType="solid" size={16} color="#DC2626" /> | Runtime reflection for wiring | Providers, constraints, and obligation tracking are compile-time—not discovered via introspection at runtime. |
| <Icon icon="ban" iconType="solid" size={16} color="#DC2626" /> | TypeScript-style `undefined` | No dual null/undefined universe. Optionals direction is `Nil` and absence—see [optionals RFC](https://github.com/forst-lang/forst/tree/main/examples/in/rfc/optionals). |
| <Icon icon="ban" iconType="solid" size={16} color="#DC2626" /> | Implicit numeric widening | Silent `int`↔`float` (and similar) conversions are rejected; casts stay explicit. |
| <Icon icon="ban" iconType="solid" size={16} color="#DC2626" /> | Dependent types and type-level computation | No type families or template metaprogramming—keeps typechecking decidable and tooling fast. |
| <Icon icon="ban" iconType="solid" size={16} color="#DC2626" /> | Runtime type mutation | No monkey patching; type definitions are fixed at compile time. |
| <Icon icon="ban" iconType="solid" size={16} color="#DC2626" /> | `ensure`-scoped immutability | Rejected: mutation drops refinement facts instead of locking fields. No borrow checker; Go stays untrusted. |
